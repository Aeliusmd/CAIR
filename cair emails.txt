In order to facilitate Californians' access to their Digital COVID-19 Vaccine Records (DCVR) and to enable the California Department of Public Health to effectively contact individuals for public health purposes such as second dose and booster dose reminders, it is necessary to send mobile phone and/or email address in the vaccination messages submitted to your local immunization registry (CAIR2, SDIR, RIDE).
 
Mobile Phone and Email address should be sent in the PID-13 field of the HL7 VXU message submitted to the immunization registry. The phone and email address can be in any order within the PID-13 field, as long as the formatting of the field is correct. An example of the formatting of the PID-13 field is shown below.  
 
Phone number field (PID-13)

PID-13.6 = area code
PID-13.7 = telephone number
 
Email address
 
PID-13.2 = NET
PID-13.3 = Internet or X.400
PID-13.4 = valid email address only

The fields the EMR needs so vaccinations can be reported to California's
immunization registry.
Background
California requires every vaccination given at our clinics to be reported to
CAIR2, the state immunization registry.
The EMR records which vaccine was given using our internal service code and a
CPT billing code. The registry accepts neither. It identifies the product by CVX,
the national vaccine code published by the CDC, and the maker by MVX.
Neither exists in the schema today, so no vaccination can currently be reported.
This document lists the fields required, and the rules worth enforcing when they
are added.
What we are asking for
1. Add the fields below to 
ServiceCodes , or to a vaccine-product table of your
design — whichever fits your pattern.
2. Enforce the four rules, so an incorrect code cannot be saved in the first place.
Fields to add
Grouped by how badly the registry needs each one. Names are suggestions —
match your own conventions.
MUST HAVE Nothing can be reported without these
FIELD TYPE WHAT IT IS
CvxCode varchar(10) The national vaccine code. This is the one the registry
matches on. Example: 43 = Hep B adult. Note it is a string,
not a number — some codes carry a leading zero (09),
which an integer column would silently destroy.
MvxCode varchar(10) Manufacturer code. Example: SKB = GlaxoSmithKline. CVX
and MVX together identify the actual brand.
IsVaccineProduct bit Separates a real vaccine from an administration fee or
supply code. Several service codes named Admin of
Vaccination… are fees and must never be reported as a
vaccine.
RegistryApprovedOn date When a clinician confirmed this mapping. Null must mean
do not report. See the safety note below.
SHOULD HAVE The registry warns or rejects without these
FIELD TYPE WHAT IT IS
RouteCode varchar(20) How it is given. C28161 = intramuscular, C38299 = subcutaneous.
The registry rejects a dose with no route. The EMR captures this
as free text today and it is almost always empty, so a per-product
default is the practical fix.
DoseAmount
DoseUnit
decimal(9,3)
varchar(12)
Standard dose, e.g. 0.5 and mL .
Ndc11 varchar(11) The product code in its 11-digit form. The existing NDCNumber
column holds a mix of 10 and 11 digit values, and a bare 10-digit
NDC is genuinely ambiguous — see rule 3.
CvxText
MvxText
varchar(200) The CDC's own wording for each code, so screens and reports can
show a name rather than a number.
NICE TO HAVE Improves quality, not blocking
FIELD TYPE WHAT IT IS
BodySiteCode varchar(10) Default injection site, e.g. LD = left deltoid.
VisDocumentCode
VisPublishedOn
varchar(40)
date
The patient information sheet given with the vaccine. The
registry asks for it on doses we administered.
EffectiveFrom
EffectiveTo
date Lets one service code carry different codes over time.
Matters for influenza — see rule 4.
RegistryApprovedBy varchar(100) Who signed it off, alongside the date.
Four rules worth enforcing in the schema
These matter more than the field list. A wrong code here lands on a patient's
permanent state immunization record.
1 · CVX must come from a list, never free text
Please load the CDC's published code list into a reference table and make the
field a lookup rather than a text box. The CDC publishes it as plain pipe
delimited text, no licence or login:
https://www2a.cdc.gov/vaccines/iis/iisstandards/downloads/cvx.txt —
289 codes, and the same for mvx.txt . A typo in a free-text CVX field is a
different vaccine, silently.
2 · Only Active CVX codes for products still in use
The CDC list carries a status per code. 118 of the 289 are Inactive — retired
products, kept in the list only so historical records can still be transmitted.
Using one for a vaccine given today misrepresents what was administered.
Nothing about the number itself signals this. Rabies is the easy trap: 18
reads like a perfectly ordinary code, but it was retired and the current one is
176 . The status column is the only way to tell, so it is worth blocking inactive
codes at entry rather than relying on whoever fills the field.
3 · Store NDC as 11 digits, or keep its dashes
A bare 10-digit NDC cannot be converted reliably. 4928101050 could be any
of three different products, depending on where the segment boundaries fall:
4928101050  →  4928-1010-50  →  04928101050
            →  49281-010-50  →  49281001050
            →  49281-0105-0  →  49281010500
There is no way to tell them apart from the digits alone. If the EMR captures
the dashes at entry, or stores the 11-digit form, the ambiguity disappears at
the source.
4 · Influenza changes almost every year
One service code named Vaccine: Influenza cannot carry one CVX forever
— the formulation changes each season, and the preservative-free and
preserved presentations are different codes (150 and 158) even though
they are the same vaccine. Either create a new service code each season, or
add the EffectiveFrom / EffectiveTo dates above. Worth deciding now
rather than at the first flu season.
Safety: a null approval date must mean "do not report"
Please make the default off. A vaccine with no clinician sign-off should be
held back and flagged, never reported with a guessed code. It is the
difference between a visible gap, which someone can fix, and a wrong entry
on a patient's medical record, which nobody notices.
Two things worth fixing while you are in there
Both showed up while working out what the registry would need. Neither is
caused by CAIR2, and both are worth correcting regardless.
Some vaccine service codes carry a billing code that is not a vaccine
SERVICE CODE CPT WHAT THAT CPT ACTUALLY IS
Vaccine: Influenza 86710 An influenza antibody lab test — not a vaccine at all
y
Vaccine: H1N1 90782 A deleted code for administering an injection, not a
product
Vaccine: Td 99070 A generic supplies and materials code
These cannot be mapped to a vaccine code until the underlying billing code is
corrected, so they are worth looking at early.
Route and lot number are almost never filled in
The vaccine record has fields for route, body site, lot number and expiry, but
they are empty on essentially every dose. Route is the one that blocks
reporting outright. A per-product default in the schema covers it, but making
the fields required at entry would be the stronger fix.
